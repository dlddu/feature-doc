## 1. 서비스 개요 (참고)

**FeatureDoc** — GitHub 저장소에 연결해 그 저장소가 제공하는 최종 사용자용 기능을 LLM으로 발견·표현·관리하는 도구. 자세한 정체성은 [`values.md`](../values.md).

## 2. 여정 정의

**대상 사용자 (페르소나)**
Pre (P1) — 자기 사이드 프로젝트나 회사 서비스 저장소 하나를 들고 오는 엔지니어. 코드는 잘 알지만 "최종 사용자가 이 제품으로 무엇을 할 수 있는지"를 글로 정리한 적이 없다. 절반 이상 모바일에서 쓴다. 자세한 정의는 [README §1](./README.md#1-페르소나).

**진입 맥락**
문서화 필요를 느끼던 차에 도구를 알게 되어 처음 들어온다. 아직 계정도 없고, 이 도구가 자기 코드를 어디까지 들여다보는지 모른다.

**트리거**
"기능 목록을 누가 물어보면 매번 코드를 뒤져서 대답하고 있다"는 자각. 또는 새 팀원·PO에게 제품 능력을 설명해야 하는 일이 생김.

**사용자 목표**
자기 저장소를 **안전하다고 납득한 범위 안에서** 이 도구에 열어주고, 비용이 감당 가능하다는 확인까지 마친 뒤 첫 분석을 거는 것.

**완료 기준**
분석 작업 1건이 큐에 등록되고 화면이 "분석을 시작했습니다" 상태로 전환됨. (로그로 확인 가능: `analysis` 레코드 생성 + 큐 등록 이벤트)

> 이 여정은 **사용자가 제품을 가장 의심하는 구간**이다. 모든 단계의 마이크로카피가 "읽기 전용 최소 권한 / 당신이 고른 저장소만 / 언제든 회수 가능 / 호출은 당신의 키로"를 짧게 반복해야 한다.

## 3. 단계별 상세

### `STP-sign-in` 본인 확인하고 들어오기

- **사용자 행동**: GitHub 계정으로 로그인해 "이 인스턴스에서의 나"를 만든다
- **터치포인트**: 로그인 화면(미인증 상태 — 와이어프레임·목업 미표현, [doc-tracker 수용된 위험](../doc-tracker.md) 참조), GitHub OAuth 동의 화면
- **생각·감정**: "또 계정 만들어야 되나" — 가입 자체보다 *권한 범위*를 본다
- **페인포인트 / 이탈 위험**: OAuth 동의 화면의 요청 범위가 넓어 보이면 여기서 바로 창을 닫는다 → 로그인 단계의 OAuth 스코프는 신원 확인에 필요한 최소로 두고, 저장소 접근은 다음 단계(App 설치)에서 별도로 요청해 **두 권한을 섞지 않는다**
- **연결 AC**: AC4.8

### `STP-grant-repo-access` 들여다볼 범위를 내가 정하기

- **사용자 행동**: GitHub App 설치를 시작하고, GitHub 설치 화면에서 접근을 허용할 저장소를 직접 고른다
- **터치포인트**: S01 자격증명 등록, GitHub App 설치 페이지
- **생각·감정**: "내 전체 계정을 주는 건 아니지?" — 이 여정에서 경계심이 가장 높은 순간
- **페인포인트 / 이탈 위험**: 외부 App에 저장소 접근을 허용하는 행위 자체가 심리적 장벽(F1) → "읽기 전용 최소 권한만 요청합니다 / 고른 저장소에만 접근합니다 / 언제든 설치를 해제할 수 있습니다"를 약관 안쪽이 아니라 **설치 버튼 바로 위**에 노출
- **연결 AC**: AC4.1, AC4.3

### `STP-register-llm-key` 분석 비용을 낼 키 맡기기

- **사용자 행동**: 자기 LLM API Key를 입력해 등록한다
- **터치포인트**: S01 자격증명 등록
- **생각·감정**: "이 키가 어디 저장되는데?" — 저장소 권한보다 키 유출을 더 무겁게 본다
- **페인포인트 / 이탈 위험**: 저장 방식 설명이 없으면 등록을 미루고 앱을 닫는다 → 평문 미저장·식별자만 표시·호출 직전에만 복호화·언제든 교체/폐기 가능을 입력란 옆에 한 줄씩. 폐기 시 진행 중 분석의 처리 정책(중단/현재 호출까지 완료)도 미리 명시
- **연결 AC**: AC4.2, AC4.3

### `STP-pick-target` 분석할 저장소와 브랜치 고르기

- **사용자 행동**: 저장소 URL과 대상 브랜치를 지정한다. 재방문이라면 홈에서 기존 저장소로 바로 들어가거나 새 저장소를 추가한다
- **터치포인트**: S02 저장소 목록(홈, 재방문 시작점), S03 저장소 연결
- **생각·감정**: "일단 제일 작은 repo로 한번 해보자" — 첫 시도는 대개 저위험 대상을 고른다
- **페인포인트 / 이탈 위험**: App 접근 범위 밖 저장소를 골랐을 때 단순히 "실패"라고만 하면 사용자는 원인을 모른 채 멈춘다 → 실패 메시지에서 **설치 범위에 추가하는 경로**로 바로 보낸다(`STP-grant-repo-access` 재진입)
- **연결 AC**: AC1.1

### `STP-confirm-cost` 비용을 확인하고 시작 누르기

- **사용자 행동**: 예상 LLM 호출 규모와 추정 비용을 확인하고 "분석 시작"을 누른다
- **터치포인트**: S03 저장소 연결(pre-flight 추정 영역 + 시작 버튼)
- **생각·감정**: "얼마 나올지 모르면 못 누르지" → 숫자를 보고 "이 정도면 괜찮네"
- **페인포인트 / 이탈 위험**: 비용이 모호하면 시작을 무기한 미룬다(F2) → 예상 호출 횟수와 추정 비용 범위를 **시작 버튼 바로 위**에. 추정 없이 시작할 수 있는 우회 경로를 만들지 않는다. 분석은 명시적 트리거로만 시작하고 자동으로 시작되지 않는다
- **연결 AC**: AC1.1, AC4.6

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 재방문 사용자 (자격증명 이미 등록) | 홈에서 시작해 인증·설치·키 단계를 건너뜀 | `STP-pick-target` |
| App 접근 범위 밖 저장소 지정 | "접근할 수 없습니다 + 설치 범위에 추가하기" 경로 안내 | `STP-grant-repo-access` |
| URL 오타·존재하지 않는 저장소 | 입력 즉시 검증 실패 표시, 큐에 등록하지 않음 | `STP-pick-target` |
| LLM Key 미등록 상태로 저장소 추가 시도 | 키 등록 화면으로 우회 후 원래 위치로 복귀 | `STP-register-llm-key` |
| 큐 등록 실패 (운영 측 문제) | 실패를 사용자에게 표시하고 재시도 제공 (AC1.5의 단계별 재시도가 여기서도 작동) | `STP-confirm-cost` |
| 키 등록 중 앱 이탈 | 설치된 App 범위는 보존됨, 다음 진입 시 키 등록만 남은 상태로 이어하기 | `STP-register-llm-key` |
| 로그아웃 | 세션 즉시 무효화, 다음 진입은 처음부터 | `STP-sign-in` |
