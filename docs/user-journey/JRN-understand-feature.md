## 1. 서비스 개요 (참고)

[`values.md`](../values.md) 참조. 이 여정은 V3("비개발자도 제품의 능력을 한눈에 이해할 수 있다")가 실제로 지켜지는지를 검증하는 여정이다.

## 2. 여정 정의

**대상 사용자 (페르소나)**
Roo (P2) — 코드를 직접 읽지 못하지만 제품의 능력을 정확히 알아야 하는 동료(PO·기획·CS·신규 입사자). 모바일 100%. 개발자 용어가 섞이면 즉시 신뢰를 잃는다. 자세한 정의는 [README §1](./README.md#1-페르소나).

**진입 맥락**
Pre가 분석을 끝내 둔 저장소를 공유받은 상태. 자기가 분석을 돌린 적은 없고, 앞선 세 여정을 겪지 않았다. **여기가 P2의 첫 화면이다.**

**트리거**
회의 전 준비, 고객 문의 대응, 스펙 확인처럼 "이 기능이 정확히 뭘 하는지 지금 알아야 하는" 순간. 또는 Pre가 링크를 보냄.

**사용자 목표**
기능 하나를 1~2분 안에 이해해서, **자기 말로 남에게 설명할 수 있는 상태**가 되는 것. 이해가 안 되는 부분이 있으면 개발자를 붙잡지 않고 그 자리에서 남겨두는 것.

**완료 기준**
그 기능의 인수 시나리오를 끝까지 읽음. 모호한 부분이 있었다면 편집 제안 1건이 등록됨. (로그로 확인 가능: feature 조회 완료 + 제안 레코드)

> P2는 분석을 트리거하지 않고, 후보를 승인하지 않으며, **확정된 feature 위에서만** 읽고 제안한다. 이 분리가 권한 격리와 맞물려 운영적으로도 안전하다.

## 3. 단계별 상세

### `STP-open-shared` 공유받은 기능 열기

- **사용자 행동**: 링크를 열고 로그인한 뒤, 자기에게 권한이 있는 저장소의 feature 목록에서 하나를 고른다
- **터치포인트**: 공유 링크, 로그인 화면, 저장소·feature 목록(S02 계열)
- **생각·감정**: "회의 10분 전인데 이거 빨리 봐야 해" — 설정이나 온보딩을 참을 여유가 없다
- **페인포인트 / 이탈 위험**: 로그인 후 앞선 여정(App 설치·키 등록) 화면으로 유도되면 P2는 "나는 개발자가 아닌데"라며 이탈한다 → **P2 진입 경로에는 자격증명 설정이 나타나지 않아야 한다.** 권한이 없는 저장소는 목록에 노출조차 되지 않는다
- **연결 AC**: AC4.8, AC4.7

### `STP-grasp-behavior` 위에서 아래로 읽어 이해하기

- **사용자 행동**: 인수 시나리오를 순서대로 읽는다. 중간에 멈추지 않고 끝까지 읽히면 성공
- **터치포인트**: S08 인수 시나리오
- **생각·감정**: "아, 만료된 토큰으로 시도하면 이렇게 되는구나" — 막히는 지점이 하나라도 있으면 "역시 개발자한테 물어봐야겠다"로 바뀐다
- **페인포인트 / 이탈 위험**: 개발자 용어가 한 줄이라도 남아 있으면 그 지점에서 읽기를 포기한다(F5) → **막히는 지점의 존재 자체가 표현 결함의 신호**다. 이 여정의 이탈 지점 로그는 V3 검수의 1차 데이터로 쓴다
- **연결 AC**: AC2.3

### `STP-check-scope` 이 기능이 무엇에 얽혀 있는지 훑기

- **사용자 행동**: 의존성을 카테고리별 목록으로 훑어 영향 범위를 감으로 잡는다
- **터치포인트**: S09 종단 의존성(카테고리 목록)
- **생각·감정**: "이거 건드리면 로그인 쪽도 같이 영향 받는 거네" — 일정·리스크 판단의 재료
- **페인포인트 / 이탈 위험**: 그래프와 기술 용어 라벨(예: "미들웨어")은 P2에게 의미가 전달되지 않는다 → 카테고리에 자연어 설명 라벨을 붙인다("외부 인터페이스 = 어디서 호출되는지"). 이 단계는 선택적이며 건너뛰어도 여정이 완료된다
- **연결 AC**: AC2.4

### `STP-flag-ambiguity` 이상한 부분을 자연어로 넘기기

- **사용자 행동**: "이 부분 무슨 뜻인지 모르겠어요" 수준의 한 줄을 남겨 LLM에게 개선을 요청하고, 제안된 diff를 보고 넘긴다
- **터치포인트**: S10 LLM 보조 편집
- **생각·감정**: "뭐가 문제인지 정확히는 모르겠는데 이상해" — 이 막연한 감각을 그대로 위임할 수 있어야 한다
- **페인포인트 / 이탈 위험**: 정확한 수정안을 요구하는 UI면 P2는 아무것도 남기지 못하고 나간다 → 문제 지적만으로도 요청이 성립해야 한다. P2의 제안이 확정 문서를 즉시 바꾸지 않고 P1 검토를 거친다는 점이 화면에 보여야 서로 안심한다
- **연결 AC**: AC3.1, AC3.4

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 권한 없는 저장소 링크를 받음 | 목록·상세 모두 미노출. 소유자에게 공유 요청 경로 안내 | 여정 종료 |
| 읽다가 용어에서 막힘 | 그 자리에서 제안 남기기로 연결 | `STP-flag-ambiguity` |
| 의존성 확인 없이 종료 | 정상 흐름 (선택 단계) | 여정 종료 |
| P2의 제안이 P1 편집과 겹침 | P1의 충돌 결정 흐름으로 넘어감 | [`JRN-follow-code-change`](./JRN-follow-code-change.md) `STP-resolve-conflict` |
| 모바일에서 링크가 앱 대신 브라우저로 열림 | 동일 화면이 모바일 웹에서도 그대로 동작해야 함 (AC4.4) | `STP-open-shared` |
