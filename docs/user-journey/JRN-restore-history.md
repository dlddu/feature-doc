## 2. 여정 정의

**대상 사용자 (페르소나)**
Pre (P1). P2는 거의 진입하지 않는다 — 복원은 문서의 최종 상태를 바꾸는 행위라 소유자의 결정이다.

**진입 맥락**
문서를 쓰다가/읽다가 "이거 예전엔 이렇지 않았는데"라는 위화감을 느낀 상태. 어느 시점에 무엇 때문에 바뀌었는지 모른다.

**트리거**
자동 재분석이 잘못된 갱신을 넣었다는 의심, LLM 편집을 잘못 승인했다는 자각, 또는 "이 기능 문서가 어떻게 진화해왔지"라는 회고 욕구.

**사용자 목표**
원인이 된 변경을 특정하고, 되돌릴지 그대로 둘지 **근거를 갖고** 결정하는 것.

**완료 기준**
문제의 변경을 특정하고, 특정 시점으로 복원하거나 "현재 상태 유지"를 선택함. (로그로 확인 가능: 이력 조회 이벤트 + 복원 실행 레코드 또는 명시적 종료)

> 이 여정이 존재한다는 사실 자체가 [`JRN-review-feature`](./JRN-review-feature.md)의 편집과 [`JRN-follow-code-change`](./JRN-follow-code-change.md)의 자동 갱신을 **되돌릴 수 있게** 만든다. 되돌릴 수 없는 편집은 사용자를 신중하게 만드는 게 아니라 손을 대지 않게 만든다.

## 3. 단계별 상세

### `STP-open-history` 이 기능이 어떻게 변해왔는지 열기

- **사용자 행동**: 검수 화면에서 변경 이력 진입점을 눌러 시간순 변경 목록을 연다
- **터치포인트**: S08 인수 시나리오(이력 진입점), 이력 화면(**미제작 — S11 후보**)
- **생각·감정**: "언제부터 이렇게 됐지?" — 원인을 찾기 전까지는 문서 전체를 못 믿는 상태
- **페인포인트 / 이탈 위험**: 이력 진입점이 검수 화면 깊숙이 있으면 이 여정 자체가 시작되지 않고, 사용자는 문서를 손으로 고치거나 방치한다 → 진입점을 feature 상세에서 한 번에 닿는 위치에 둔다
- **연결 AC**: AC3.4

### `STP-trace-origin` 누가 무엇을 바꿨는지 짚기

- **사용자 행동**: 각 변경의 출처(자동 분석 / 사용자 by LLM / 사용자 직접)와 변경 내용을 훑어 원인 지점을 특정한다
- **터치포인트**: 이력 화면(**미제작**)
- **생각·감정**: "아 이건 자동이 넣은 거구나" — 출처를 알면 대응이 달라진다. 자동이면 충돌 정책을 의심하고, 자기 편집이면 그냥 되돌린다
- **페인포인트 / 이탈 위험**: 출처가 없거나 "수정됨"으로 뭉뚱그려지면 원인을 특정할 수 없어 복원이 도박이 된다 → 3종 출처가 모든 변경에 예외 없이 붙어야 하고, 모바일 화면에서 한눈에 구분돼야 한다
- **연결 AC**: AC3.4

### `STP-restore-point` 되돌릴지 그대로 둘지 정하기

- **사용자 행동**: 특정 시점의 상태를 미리 보고 복원하거나, 확인만 하고 현재 상태를 유지한 채 나간다
- **터치포인트**: 이력 화면(**미제작**), S08 인수 시나리오(복원 결과 확인)
- **생각·감정**: "되돌리면 그 뒤 변경들은 어떻게 되지?" — 복원의 파급이 안 보이면 버튼을 못 누른다
- **페인포인트 / 이탈 위험**: 복원 결과를 미리 볼 수 없으면 아무도 복원하지 않는다 → 복원 전 diff 미리보기를 제공하고, 복원 자체도 하나의 변경으로 이력에 기록해 다시 되돌릴 수 있게 한다
- **연결 AC**: AC3.4

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 원인이 자동 재분석으로 판명 | 충돌 정책 문제일 수 있음. 해당 feature의 충돌 결정으로 이동 | [`JRN-follow-code-change`](./JRN-follow-code-change.md) `STP-resolve-conflict` |
| 원인이 자기 LLM 편집으로 판명 | 해당 시점으로 복원하거나 재편집 | [`JRN-review-feature`](./JRN-review-feature.md) `STP-request-edit` |
| 복원했는데 그것도 아님 | 복원 자체가 이력에 남으므로 다시 되돌리기 가능 | `STP-restore-point` |
| 확인만 하고 유지 | 정상 종료 (회고 목적의 진입) | 여정 종료 |
| 삭제된 feature의 이력을 보고 싶음 | soft delete 보관 기간 내라면 이력 조회·복구 가능 | `STP-open-history` |
