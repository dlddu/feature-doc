# 주석 정책 (Comment Policy)

`dlddu/feature-doc`의 주석은 **코드·저장소 문서·PR·커밋 메시지 어느 쪽으로도 복원되지 않는
지식**만 담는다. 읽는 사람이 다른 곳에서 확인할 수 있는 내용을 주석이 되풀이하면 drift다 —
값이 없을 뿐 아니라, 원본만 고쳐질 때 조용히 거짓이 되기 때문이다.

이 문서는 규칙(진입점)이다. 판정 결과는 [ledger.md](ledger.md), 판정 근거 상세는
[passes/](passes/)에 둔다 — 세 역할을 한 파일에 섞지 않는다. 원장의 불변식과 집계는
`scripts/check-comment-ledger.py`가 CI에서 강제하고 출력한다.

## 복원 경로 넷

주석의 내용이 다음 넷 중 어디서든 확인되면 주석의 자리가 아니다:

1. **코드 자체** — 선언 이름·시그니처·제어 흐름·SQL·오류 문자열이 이미 말하는 것.
2. **저장소 문서** — `docs/` 아래(PRD · 테스트 문서 · doc-tracker · README)가 규정하는 것.
3. **PR 제목·본문·리뷰 코멘트** — 슬라이스·task·PR 번호를 담은 작업 흔적의 자리.
4. **커밋 메시지** — 경위서술의 자리.

## 유지 대상 (이 밖은 제거 후보)

- **기계가 읽는 주석** — 정책 대상이 아니며 지문·판정 모두에서 제외한다:
  `:#!|//go:|nolint|eslint-|@ts-|prettier-ignore|/// <reference|istanbul ignore|c8 ignore|# ?noqa|`
  `# ?type:|# ?pragma|# ?pylint:|# ?fmt:|shellcheck |# ?syntax=|yaml-language-server:|검증 시나리오:|mock-exception:`
  앞부분은 도구 공통(유형 템플릿 고정부)이고 뒤의 두 항목만 이 레포 고유다.
  - Rust 속성 `#[...]`·`#![...]` — `#`로 시작하지만 주석이 아니다(컴파일러가 읽는다). `.rs`는
    C 언어군이라 `#`가 주석 시작이 아니어서, 이제 별도 필터 없이 자동으로 빠진다.
  - `// 검증 시나리오:` — `tools/check-scenario-e2e.py`가 파싱하는 매핑 선언.
  - `/// <reference types=... />` — TypeScript 컴파일러 지시자.
  - shebang — 인터프리터가 읽는다.
  - `mock-exception:` — e2e mock-policy의 표기 규약 주석.
- **doc 주석** — Rust는 `pub` 항목의 **요약 1줄** `///`과 모듈 머리 `//!`를 유지하고, TS는
  export 함수의 JSDoc 요약 1줄을 유지한다. 다만 doc 주석 본문이 시그니처·타입·`docs/prd/`·
  `docs/test/`·`docs/doc-tracker.md`를 되풀이하는 부분(AC 조항 재진술, 슬라이스 경위 서술)은
  제거 대상이다. rustdoc 링크(`[`…`]`)만으로 이루어진 교차 참조는 이름에서 복원되므로 링크를
  위해서만 문장을 남기지 않는다.
- **복원 불가능한 지식** — 상류 API의 **문서화되지 않은 동작·거부 조건**(GitHub App·OAuth,
  Anthropic Messages·OpenAI Responses — 예: sampling parameter를 400으로 거부), SQLite 단일
  writer·sqlx 체크섬 같은 **저장소 제약의 함정**, 봉투 암호화·자격증명 비노출 불변식이
  **왜 그 자리에서 지켜져야 하는지**, 워커 임대·큐 드레인·claim/lease 같은 **동시성 계약**,
  `kubectl scale`·rollout이 pod 정착 전에 돌아오는 것 같은 **실패 모드의 함정**, stub 분기가
  real과 갈리는 지점(충실도 경계).

## 충돌 시 기본 방향

코드·문서·이력이 SSOT다. 주석이 그것들과 어긋나면 **주석이 틀린 것으로 본다** — 주석은 아무도
검증하지 않기 때문이다.

- 복원 가능하면 → 주석을 지운다. 원본이 부실해서 복원이 안 되는 것이면, 주석을 남기는 대신
  **원본(문서·이름·커밋 메시지)을 고친다**.
- 복원 불가능하면 → 남긴다.
- **애매하면 남긴다.** 중복 주석의 비용은 작지만, 유일한 지식을 담은 주석을 지우면 그 지식은
  어디에도 남지 않는다. 비용이 비대칭이므로 판단이 갈리는 주석은 보존하고 그 사실을
  [passes/](passes/)에 남긴다.

## 판정 절차

1. 대상 범위를 **파일 단위**로 정하고 그 범위의 주석을 위 기준으로 판정한다. 제거는 주석 행만 —
   SQL문·동작 코드는 한 글자도 건드리지 않는다.
2. 제거 근거(복원 경로)와 유지 사유를 패스 상세 `passes/<판정일>-<범위-slug>.md`에 적고,
   원장 `ledger.md`에 행을 등재한다. 행은 **범위 첫 파일 경로의 사전순** 자리에 넣는다 —
   표 끝에 덧붙이면 두 PR이 같은 줄을 고쳐 반드시 충돌한다.
3. 같은 범위의 **증분 재판정은 새 파일을 만들지 않고** 원래 패스 파일에 절을 더한다(원장 행 동일).
4. 행의 **판정 축** 칸에 그 행의 **현재 지문**에 대해 판정을 마친 복원 경로를 적는다 — 네 경로를
   모두 물었으면 `①②③④`, 일부만 마쳤으면 마친 것만, 아직 판정하지 않았으면 `—`. 묻지 않은 경로는
   적지 않는다.

### 판정하지 않은 주석을 들이는 PR (자매 모델의 기능 PR 등)

합계·잔량 같은 **공유 값을 올리지 않는다**. 대신 **자기 파일의 행**을 더하거나 고친다:

- 원장에 행이 없는 파일이면 행을 새로 만들고 판정 축을 `—`로 둔다.
- 이미 판정된 행의 파일에 주석을 더했으면 그 행의 줄 수·지문을 갱신하고 **판정 축을 `—`로
  되돌린다**(증분만 판정했으면 그 결과를 적는다). 지문이 움직인 행은 그 축이 더 이상 현재
  지문을 말하지 않기 때문이다.
- 집계(판정 완료 줄·행 수, 축별 미판정 행 수, 미등재 여부)는 **원장에 적지 않는다** —
  `scripts/check-comment-ledger.py`가 표와 실측에서 계산해 출력한다. CI가 이 게이트를 돌려
  파일 소속 유일·전수, 줄 수·지문 일치, 판정 축 표기, 표 밖 산문 없음을 강제한다. 미판정(`—`)은
  실패가 아니다 — 판정하지 않았다는 사실을 행에 남기는 것이 정상이고, 그 행은 다음 슬라이스가
  가져간다.

## 적용된 마이그레이션의 주석 — 전용 PR · 수동 repair · 사람 승인

`backend/migrations/*.sql`도 판정·정리의 대상이다. 다만 **main에 올라간 마이그레이션은 바이트
하나만 바뀌어도** sqlx가 적용 이력의 SHA-384와 대조해 운영 파드를 `VersionMismatch`로 부팅
실패시킨다(`backend/migrations/README.md`). CI는 매번 새 DB에서 돌아 이 사고를 잡지 못하므로,
이 파일들의 정리는 아래 순서를 따른다.

1. **판정** — 다른 파일과 같다. 이 파일의 주석 자리는 "그 시점에 왜 이 변경을 했는가"의 기록이므로,
   스키마 선언을 되풀이하는 문장은 제거 후보로, 당시의 의도·제약 서술은 커밋 메시지와 겹쳐도
   애묘하면 유지로 본다. **한 패스에서 마이그레이션 판정을 끝까지 모아** 한 번의 repair로 끝낸다.
2. **전용 PR** — 마이그레이션 주석 편집은 다른 주석 정리와 **섞지 않고 별도 PR 하나**로 만든다.
   PR의 `.sql` diff는 **주석 줄과 그에 딸린 빈 줄만** 바꾼다 — SQL문은 이미 적용돼 다시 실행되지
   않으므로 한 글자도 건드리지 않는다.
3. **repair 명세** — 계획의 실행 지침과 PR 본문에 **바뀐 파일마다 `version` · 파일명 · PR head 기준
   새 SHA-384(hex)** 를 표로 적고, `backend/migrations/README.md`의 repair 순서(체크섬 계산 →
   Flux suspend·API scale 0 → 정비 파드에서 `.bak` 백업 · 현재 `_sqlx_migrations` 확인 · 해당
   버전만 `UPDATE` → Flux resume → 머지 → 롤아웃 확인)와 되돌리기 방법을 그대로 옮긴다. PR head
   이미지를 쓰는 preview 환경이 기존 볼륨을 쓰는지도 사람이 확인할 항목으로 적는다.
4. **사람 게이트** — 적용된 마이그레이션을 바꾸는 정리는 위험도와 무관하게 **자동 승인하지
   않는다**. 사람은 repair(README 1~4단계)를 **직접 마친 뒤** 승인하고, 승인 사유에 repair 완료
   여부가 적혀 있지 않으면 실행하지 않는다.
5. **머지 직전 대조** — PR head의 각 `.sql` SHA-384를 다시 계산해 3의 표와 **정확히 같은지**
   확인한다. 다르면 머지하지 않고 사람에게 되돌린다 — 운영 DB는 이미 표의 값으로 고쳐져 있다.
   같으면 **곧바로** 머지한다(Flux resume과 머지 사이가 길면 구 이미지 파드가 새 체크섬과
   어긋난 채 재기동될 수 있다).
6. **수렴 검증** — 롤아웃 완료, 부팅 로그에 `VersionMismatch` 없음, `/hello` 응답 확인. 실패하면
   `.bak` 복원 + 이미지 되돌리기를 사람에게 요청한다.
7. **기록** — 패스 상세에 repair한 버전과 체크섬(이전·이후)을 남긴다. `backend/migrations/README.md`의
   불변 원칙 문구는 그대로 둔다 — 이 절차는 사람 게이트를 거친 명시적 예외이지, 평소 편집을
   허용하는 규칙 변경이 아니다.

## 범위 — 레포 전체 − 제외

범위는 **포함 목록이 아니라 「레포 전체에서 제외를 뺀 것」**이다. 포함 목록은 레포가 자라며 생긴
새 디렉터리를 조용히 흘린다 — 그 안의 주석은 지문에 잡히지 않고, drift가 있어도 신호가 없다.
그래서 무엇을 넣을지는 정하지 않고, **무엇을 뺄지만** 원칙으로 정한다.

제외는 다음 세 부류뿐이다. 이 밖의 이유("CI 스크립트라서", "설정 파일이라서")로는 빼지 않는다.

| 부류 | 왜 빼는가 | 빼는 것 |
|---|---|---|
| ① 복원 원본 | 저장소 문서는 판정의 **기준**이다. 대상에 넣으면 기준이 자기 자신을 심사한다 | `docs/`, 모든 `*.md` |
| ② 편집 불가 | 지워도 재생성·재설치되어 판정할 의미가 없다 | 벤더·의존성·빌드 산출물 디렉터리(`node_modules/`·`dist/`·`target/`·`vendor/`·`coverage/` 등), 락 파일, 머리 5줄에 `DO NOT EDIT`·`@generated` 표식이 있는 파일 |
| ③ 주석 문법 없음 | 주석이라는 개념이 없어 패턴이 무엇을 잡든 오탐이다 | 바이너리, NONE 언어군(JSON·CSV·TXT·키·스냅샷 등 데이터·자산) |

파일은 **이름으로** 언어군 하나에 든다(C · HASH · DASH · MIXED · MARKUP · NONE). 그래서
`.github/workflows/*.yml`·`Dockerfile`·`backend/Cargo.toml`·`deploy/k8s/.gitignore`도 **대상이다** —
주석 문법이 있고 위 세 부류에 들지 않기 때문이다(2026-09-26 범위 개정으로 들어왔다). 확장자로
가르지 못한 텍스트 파일은 첫 줄이 `#!`이면 HASH 언어군이고, 그래도 남으면 **미분류**다. 미분류는
경로가 지문에 들어가 생기거나 사라질 때 감지가 돌게 한다 — 범위가 레포 성장을 따라가지 못할 때
조용히 새지 않게 하는 장치다. 해소는 두 갈래: 데이터·자산이면 아래 블록에 더하고, 표에 없는 새
언어면 유형 템플릿의 언어군 표를 고쳐야 한다.

레포 고유 제외는 이 문서에 둔다 — 범위가 낡았을 때의 수정이 **이 레포 PR로 끝나야** 하기
때문이다. 정보 문자열이 `comment-scope-exclude`인 코드 블록에 한 줄에 ERE 하나를 적고, 줄마다
어느 부류(①②③)인지를 블록 바로 위에 적는다. 부류를 댈 수 없는 제외는 둘 수 없다. **현재 이
레포에는 그런 제외가 없다**(미분류 0건) — 블록이 없으면 위 고정부만 적용된다. 블록을 두면
그 ERE가 깨지는 순간 감지 스크립트가 실패하므로, 뺄 것이 실제로 생겼을 때만 만든다.

- **판정 표면 밖**: 주석의 정확성(코드와 맞는가)·문서·커밋 메시지 자체의 품질. 다만 되풀이된
  주석이 낡아 틀려 있으면 그것은 제거 근거를 강화한다.

## 지문과 사각지대

원장의 지문은 대상 주석 줄을 정규화·정렬해 해싱한 값으로, **주석이 추가·수정·삭제될 때만
변한다** — 주석과 무관한 코드 변경에는 반응하지 않는다. 어느 표면도 줄 번호·식별자 이름을
담지 않으므로, 주석이 파일 안에서 옮겨 가거나 함수 이름이 바뀌어도 값은 그대로다.

**표면은 셋이고, 원장은 표면마다 표를 하나씩 둔다.**

| 표면 | 무엇을 잡는가 | 어떻게 | 해시 줄 |
|---|---|---|---|
| **L** 줄머리 주석 | 언어군 패턴(`//`·`#`·`--`·`<!--`)에 걸리는 줄 | 줄 패턴 | `경로:본문` |
| **D** docstring 본문 | Python 모듈·클래스·함수(async 포함)의 docstring 본문, 들여쓰기 정리 후 줄 단위 | `ast` | `D:경로:본문` |
| **E** 줄 끝·줄 중간 주석 | 코드 **뒤에** 오는 주석(`let x = 1; // 이유`, 줄 중간에서 여는 블록 주석) | Python은 `tokenize`, C 언어군·`#` 계열·`--` 계열은 문자열 상태를 따라가는 줄 스캐너 | `E:경로:본문` |

L만 첫 진단 줄(`lines=… files=… unclassified=…`)에 세어지고, D·E는 둘째 줄
(`docstring=줄/파일 eol=줄/파일 unparsed=N`)에 따로 나온다. 세 표면 모두 `scripts/check-comment-ledger.py`가
원장과 대조하며, 파싱에 실패한 파일은 `unparsed`로 드러난다 — 표면에서 조용히 빠지지 않게
하기 위해서다. 기계가 읽는 주석은 E에서도 빼되, **지시자 뒤에 사람이 덧붙인 사유**는 사람의
문장이므로 E로 남는다.

남은 사각지대는 다음뿐이다 — 이것들은 판정 표면 밖이고, 유형 템플릿(control plane)이 소유한다.

- MIXED(`.html`·`.vue`·`.svelte`) · MARKUP(`.xml`·`.svg` 등) 언어군의 줄 끝·줄 중간 주석.
- 줄 중간 `#`이 주석이 아닌 `#` 계열 파일(`Dockerfile`·`.gitignore`류·`.env`·ini/cfg)의 줄 끝 주석.
- `*`로 시작하지 않는 블록 주석의 연속 줄, Python 밖의 docstring 성격 문자열.
- 줄 스캐너의 문자열 추적 한계(JS 정규식 리터럴, JSX 텍스트 안의 따옴표·`//`, Rust 수명 표기).

오탐·누락 모두 결정적이다. 그래서 **판정은 언제나 파일을 읽어서** 하고, 위 목록에 **없는**
사각지대가 실제로 발화했을 때만 그것을 판정 기록에 남긴다 — 이미 알려진 사각지대를 판정마다
다시 인계하지 않는다.
