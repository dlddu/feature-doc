# 주석 정책 (Comment Policy)

`dlddu/feature-doc`의 주석은 **코드·저장소 문서·PR·커밋 메시지 어느 쪽으로도 복원되지 않는
지식**만 담는다. 읽는 사람이 다른 곳에서 확인할 수 있는 내용을 주석이 되풀이하면 drift다 —
값이 없을 뿐 아니라, 원본만 고쳐질 때 조용히 거짓이 되기 때문이다.

이 문서는 규칙(진입점)이다. 판정 결과는 [ledger.md](ledger.md), 판정 근거 상세는
[passes/](passes/)에 둔다 — 세 역할을 한 파일에 섞지 않는다.

## 복원 경로 넷

주석의 내용이 다음 넷 중 어디서든 확인되면 주석의 자리가 아니다:

1. **코드 자체** — 선언 이름·시그니처·제어 흐름·SQL·오류 문자열이 이미 말하는 것.
2. **저장소 문서** — `docs/` 아래(PRD · 테스트 문서 · doc-tracker · README)가 규정하는 것.
3. **PR 제목·본문·리뷰 코멘트** — 슬라이스·task·PR 번호를 담은 작업 흔적의 자리.
4. **커밋 메시지** — 경위서술의 자리.

## 유지 대상 (이 밖은 제거 후보)

- **기계가 읽는 주석** — 정책 대상이 아니며 지문·판정 모두에서 제외한다:
  `:[[:space:]]*#!?\[|:#!/|/// <reference|eslint-|@ts-|# ?noqa|# ?type:|# ?pragma|검증 시나리오:|mock-exception:`
  - Rust 속성 `#[...]`·`#![...]` — `#`로 시작하지만 주석이 아니다(컴파일러가 읽는다).
  - `// 검증 시나리오:` — `tools/check-scenario-e2e.py`가 파싱하는 매핑 선언.
  - `/// <reference types=... />` — TypeScript 컴파일러 지시자.
  - shebang — 인터프리터가 읽는다.
  - `mock-exception:` — e2e mock-policy의 표기 규약 주석.
- **doc 주석** — Rust는 `pub` 항목의 **요약 1줄** `///`과 모듈 머리 `//!`를 유지하고, TS는
  export 함수의 JSDoc 요약 1줄을 유지한다. 다만 doc 주석 본문이 시그니처·타입·`docs/prd/`·
  `docs/test/`·`docs/doc-tracker.md`를 되풀이하는 부분(AC 조항 재진술, 슬라이스 경위 서술)은
  제거 대상이다. rustdoc 링크(`[`…`]`)만으로 이루어진 교차 참조는 이름에서 복원되므로 링크를
  위해서만 문장을 남기지 않는다.
- **복원 불가능한 지식** — 상류 API의 **문서화되지 않은 동작·거부 조건**(GitHub App·OAuth,
  Anthropic Messages·OpenAI Responses — 예: sampling parameter를 400으로 거부), SQLite 단일
  writer·sqlx 체크섬 같은 **저장소 제약의 함정**, 봉투 암호화·자격증명 비노출 불변식이
  **왜 그 자리에서 지켜져야 하는지**, 워커 임대·큐 드레인·claim/lease 같은 **동시성 계약**,
  `kubectl scale`·rollout이 pod 정착 전에 돌아오는 것 같은 **실패 모드의 함정**, stub 분기가
  real과 갈리는 지점(충실도 경계).

## 충돌 시 기본 방향

코드·문서·이력이 SSOT다. 주석이 그것들과 어긋나면 **주석이 틀린 것으로 본다** — 주석은 아무도
검증하지 않기 때문이다.

- 복원 가능하면 → 주석을 지운다. 원본이 부실해서 복원이 안 되는 것이면, 주석을 남기는 대신
  **원본(문서·이름·커밋 메시지)을 고친다**.
- 복원 불가능하면 → 남긴다.
- **애매하면 남긴다.** 중복 주석의 비용은 작지만, 유일한 지식을 담은 주석을 지우면 그 지식은
  어디에도 남지 않는다. 비용이 비대칭이므로 판단이 갈리는 주석은 보존하고 그 사실을
  [passes/](passes/)에 남긴다.

## 판정 절차

1. 대상 범위를 **파일 단위**로 정하고 그 범위의 주석을 위 기준으로 판정한다. 제거는 주석 행만 —
   SQL문·동작 코드는 한 글자도 건드리지 않는다.
2. 제거 근거(복원 경로)와 유지 사유를 패스 상세 `passes/<판정일>-<범위-slug>.md`에 적고,
   원장 `ledger.md`에 행을 등재한다.
3. 같은 범위의 **증분 재판정은 새 파일을 만들지 않고** 원래 패스 파일에 절을 더한다(원장 행 동일).

## 적용된 마이그레이션의 주석 — 전용 PR · 수동 repair · 사람 승인

`backend/migrations/*.sql`도 판정·정리의 대상이다. 다만 **main에 올라간 마이그레이션은 바이트
하나만 바뀌어도** sqlx가 적용 이력의 SHA-384와 대조해 운영 파드를 `VersionMismatch`로 부팅
실패시킨다(`backend/migrations/README.md`). CI는 매번 새 DB에서 돌아 이 사고를 잡지 못하므로,
이 파일들의 정리는 아래 순서를 따른다.

1. **판정** — 다른 파일과 같다. 이 파일의 주석 자리는 "그 시점에 왜 이 변경을 했는가"의 기록이므로,
   스키마 선언을 되풀이하는 문장은 제거 후보로, 당시의 의도·제약 서술은 커밋 메시지와 겹쳐도
   애묘하면 유지로 본다. **한 패스에서 마이그레이션 판정을 끝까지 모아** 한 번의 repair로 끝낸다.
2. **전용 PR** — 마이그레이션 주석 편집은 다른 주석 정리와 **섞지 않고 별도 PR 하나**로 만든다.
   PR의 `.sql` diff는 **주석 줄과 그에 딸린 빈 줄만** 바꾼다 — SQL문은 이미 적용돼 다시 실행되지
   않으므로 한 글자도 건드리지 않는다.
3. **repair 명세** — 계획의 실행 지침과 PR 본문에 **바뀐 파일마다 `version` · 파일명 · PR head 기준
   새 SHA-384(hex)** 를 표로 적고, `backend/migrations/README.md`의 repair 순서(체크섬 계산 →
   Flux suspend·API scale 0 → 정비 파드에서 `.bak` 백업 · 현재 `_sqlx_migrations` 확인 · 해당
   버전만 `UPDATE` → Flux resume → 머지 → 롤아웃 확인)와 되돌리기 방법을 그대로 옮긴다. PR head
   이미지를 쓰는 preview 환경이 기존 볼륨을 쓰는지도 사람이 확인할 항목으로 적는다.
4. **사람 게이트** — 적용된 마이그레이션을 바꾸는 정리는 위험도와 무관하게 **자동 승인하지
   않는다**. 사람은 repair(README 1~4단계)를 **직접 마친 뒤** 승인하고, 승인 사유에 repair 완료
   여부가 적혀 있지 않으면 실행하지 않는다.
5. **머지 직전 대조** — PR head의 각 `.sql` SHA-384를 다시 계산해 3의 표와 **정확히 같은지**
   확인한다. 다르면 머지하지 않고 사람에게 되돌린다 — 운영 DB는 이미 표의 값으로 고쳐져 있다.
   같으면 **곧바로** 머지한다(Flux resume과 머지 사이가 길면 구 이미지 파드가 새 체크섬과
   어긋난 채 재기동될 수 있다).
6. **수렴 검증** — 롤아웃 완료, 부팅 로그에 `VersionMismatch` 없음, `/hello` 응답 확인. 실패하면
   `.bak` 복원 + 이미지 되돌리기를 사람에게 요청한다.
7. **기록** — 패스 상세에 repair한 버전과 체크섬(이전·이후)을 남긴다. `backend/migrations/README.md`의
   불변 원칙 문구는 그대로 둔다 — 이 절차는 사람 게이트를 거친 명시적 예외이지, 평소 편집을
   허용하는 규칙 변경이 아니다.

## 범위

- **대상**: `backend/src backend/tests frontend/src e2e scripts tools deploy`의 주석과
  `backend/migrations/*.sql`의 `--` 주석.
- **비대상**: 라이선스 헤더, 생성 코드·빌드 산출물(`dist/`·`target/`·`node_modules/`),
  마크다운(`docs/` 및 각 디렉터리의 README), `docs/`의 HTML, `Dockerfile`, `.github/workflows`.
- **판정 표면 밖**: 주석의 정확성(코드와 맞는가)·문서·커밋 메시지 자체의 품질. 다만 되풀이된
  주석이 낡아 틀려 있으면 그것은 제거 근거를 강화한다.

## 지문과 사각지대

원장의 지문은 대상 주석 줄을 정규화·정렬해 해싱한 값으로, **주석이 추가·수정·삭제될 때만
변한다** — 주석과 무관한 코드 변경에는 반응하지 않는다. 줄 끝 주석(`let x = 1; // 이유`)과 줄
중간에서 시작하는 블록 주석은 지문에 보이지 않으므로, 판정은 항상 파일을 읽어서 한다. 지문이
보이지 않는 주석·오탐이 늘어나면 지문 패턴을 조정하는 것을 다음 판정에서 다룬다.
