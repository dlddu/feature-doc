## `backend/migrations/0012_llm_language.sql` — 유지 14행 · 정본 지정 신설

이 파일의 머리 문단은 **어느 패스도 아직 정본으로 지정하지 않았다.** 이 패스가 지정한다.

  절반은 다른 언어로 남는다」. 두 컬럼의 **비정규화를 정당화하는 동시성 서술**이고, 코드는 두 컬럼을 읽는

    근거로 이루어졌는지 복원되지 않는다.
  - 앞 절 「사용자 쪽은 NOT NULL + 기본값 'ko' 다」는 선언 재진술이지만 같은 문장의 술어가 「이 컬럼이 생기기
    전부터 있던 사용자 행도 고른 적 없는 사용자와 같은 값을 읽는다」(마이그레이션 시점의 기존 행 처리)이므로

## 제거 후보 검토 — 세 자리를 유지로 닫는다

정책 본문: 「**애매하면 남긴다.** 이 유형은 제거 쪽으로 기울지 않는다 … 비용이 비대칭이므로 판단이 갈리는
주석은 보존하고 그 사실을 task 에 남긴다」. 이 축에서는 비용 비대칭이 한 겹 더 크다 — 제거의 비용은 주석
몇 줄이 아니라 **운영 DB repair 창**(Flux suspend → API scale 0 → `_sqlx_migrations` SHA-384 `UPDATE` →
resume)이고, 실패하면 운영 파드가 `VersionMismatch` 로 부팅하지 못한다.

1. **`content_hash` 논거 두 벌 — `0009` 11~17행 ↔ `0010` 17~20행.** 같은 명제이므로 한 벌로 줄일 수 있다.
   유지 근거: ⑴ 두 파일은 각각 자기 축의 코드 사본을 걷어 낸 정본이라 어느 쪽을 지워도 그 축의 제거 근거가
   사라진다, ⑵ `0011` 이 이미 「(0009 · 0010 의 주석과 같은 이유)」 **상호 참조형**으로 적어 세 벌이 아니라
   두 벌 + 참조 하나로 관리되고 있다, ⑶ 제거 이득 3~4행 대비 비용이 repair 창이다.
2. **`0012` 10행 앞 절 「사용자 쪽은 NOT NULL + 기본값 'ko' 다」.** 15행 DDL 의 재진술이다. 유지 근거:
   같은 문장의 술어가 기존 행 처리(마이그레이션 시점의 사실)이므로 절만 떼면 문장이 끊긴다 — 재작성이
   필요하고, 재작성은 곧 `.sql` 접촉이다.
3. **CHECK 존재 재진술 두 절 — `0009` 26행 「CHECK 가 그 어휘를 못박는다」 · `0010` 29행 「CHECK 가 확정된
   행에만 값을 요구한다」.** 둘 다 바로 아래 CHECK 절이 축자로 말한다(복원 경로 ①). 유지 근거: 문장의 주된
   술어가 어휘·NULL 의 **이유**이고 이 절은 그 이유의 귀결을 잇는 꼬리다. 2와 같은 이유로 절 단위 제거는
   재작성을 요구한다.

**이 세 자리는 다음에 이 축이 열릴 때(사람이 repair 창을 여는 전용 PR) 함께 처리할 목록이다** — 그때는
이미 `.sql` 을 고치고 있으므로 한계 비용이 0 이다. 순 제거 기대값은 **6~8행**이다.
