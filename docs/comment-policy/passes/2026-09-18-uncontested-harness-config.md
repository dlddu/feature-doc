## `tools/check-journey-prototype.js` — 무엇을 왜 지웠나

### ① 파일 머리 주석을 그대로 되풀이하는 인라인 마커 (8행)

`/* P6 (b) 보조 레이어가 기본으로 닫혀 있다 */` 류 8개. 파일 머리의 「검사」 목록이
P1~P7 각각을 이미 한 줄씩 정의하고, 각 블록의 `ok(cond, 'P6', …)` 호출이 **규칙 태그와 실패
메시지로** 같은 내용을 다시 말한다. 복원 경로 ① — 지운다.

### ② 등록부 4종의 존재 이유를 되풀이하는 블록 (3곳)

- `ARM` 위 5행: 「등록이 없는 여정 페이지는 통과시키지 않는다 — 새 여정이 이관될 때 하네스가
  조용히 공허해지는 것을 막는다」는 파일 머리 마지막 두 줄과 사실상 같은 문장이다.
- `INPUT_PROBE` 위 9행 중 앞 5행: 같은 이유. **뒤의 ⚠️ 3행은 남겼다** — 「이 등록부가 없던 시절
  두 번째 여정 페이지에서 uncaught TypeError 로 하네스가 통째 죽었다」는 **실제로 일어난 사고의
  기록**이고 어디에서도 복원되지 않는다. 파일 머리가 「아래 INPUT_PROBE 주석 참조」로 이 자리를
  가리키므로 그 참조도 유효하게 남는다.
- `SECOND_END` 위 4행: 「정상 경로의 끝은 P2 가 마지막 단계의 전진으로 확인한다」는 P2 블록의
  코드가, 「갈래가 하나뿐이면 규칙 5(g) 를 충족하지 못한다」는 모델 규칙 문서가 말한다.

### ③ 같은 문구의 5회 반복 (5행)

`ARM`의 여정 5개 각각에 붙은 `// 단계별로 "그 화면 안에서 실제 사용자가 하는 최소 입력"`.
파일 머리의 `ARM[jid][stepId] — 그 단계의 CTA 가 살아나게 하는 최소 입력 (P2)`가 원본이다.

### ④ 절 제목(구분선) (5행)

`── 여정 문서 파싱 ──` · `── 페이지 로드 ──` · `── 본 검사 ──` · `── 보고 ──` ·
`── 단계 → 소유 여정 ──`. 바로 아래 선언(`parseJourney` · `load` · 보고 `console.log`)이
이미 말한다.

### ⑤ 바로 아래 코드가 그대로 말하는 문장 (나머지)

- `expectedTarget` 위 2행 — 함수 본문 3줄이 문장 그대로다(같은 여정이면 그 단계, 아니면
  `data-goto-journey` 선언 블록).
- `PRODUCT_PATHS` 위 2행 중 순서 대응 문장 — 그 대응은 `paths.length === jr.branches.length`
  단언과 인덱스 순회가 강제한다.
- P3 블록의 「타이핑·선택이 관측 가능한 상태 변화를 만드는가」 2행 — 바로 아래 `INPUT_PROBE[jid](…)`

- `// 선택(select)도 동작하는가` 1행 — 다음 줄 단언 메시지가 `Provider 가 실제 <select> 가 아니다`.

## `tools/check-journey-prototype.js` — 판단이 갈려 **남긴** 것

- **`PRODUCT_PATHS` 안의 상황 주석 전부**(「자동 채택하지 않는다 — 그 후보는 여전히 미결정이다」 류
  20여 행). 변수명(`notAdopted`·`kept`·`dropped`)과 DOM id 가 절반은 말하지만, **여정 문서 §4 의
  「상황」이 이 화면에서 무엇으로 관측되는가**라는 대응은 이 자리에만 적혀 있다. 비용이 비대칭이라
  남긴다.
- **`data-scenario` 훅을 쓰는 이유**(「운영 측 실패라 사용자가 일으킬 수 없다 — 보조 레이어에서
  장전한다」 4곳). 코드는 클릭만 하고, **왜 사용자 행동이 아닌 훅인지**는 복원되지 않는다.
- **단언이 공허해지지 않게 하는 선택의 근거** — 「`openai` 의 `sk-` 는 `sk-ant-` 의 접두사라 이
  자리에서 쓰면 검사가 공허해진다」, 「두 회차의 변경 기능 수가 3 과 1 로 겹치지 않아 단언이
  공허해지지 않는다」. 뮤테이션 내성의 근거이며 어디에서도 복원되지 않는다.
- **P1 해시 변경 블록의 3행** — 「뮤테이션(hashchange 핸들러 제거)이 잡아낸 사각이다」는 그 검사가
  왜 존재하는지의 기록이다. 이 블록만은 P-마커를 지우지 않았다(마커가 아니라 사고 기록이다).
- **`SECOND_END` 3개 항목 위의 「여정 문서 §4 의 …」 3쌍** — 그 갈래가 왜 분기표의 행이 아니라
  화면 안의 행동으로 표현되는지의 판단 근거다. 문서를 읽어도 「분기표에 없다」는 사실만 나오고,
  그래서 이렇게 모델링했다는 결정은 나오지 않는다.
- **ARM 안의 완료 기준 주석 6행**(「후보 4건을 전부 결정해야 다음으로 넘어간다」 류). 그 화면의
  전진 조건이며, 최소 입력이 왜 그것인지를 설명한다.

## `backend/src/config.rs` — 판단이 갈려 **남긴** 것

- **모듈 머리 주석 5행** — 「`#[derive(Debug)]` 의 **의도된 부재**」는 **코드에 없는 것**이라
  읽어서 복원할 수 없다. `(AC4.3: credentials must not reach logs)` 인용도 여기서는 남겼다 —
  그 부재가 무엇을 지키는지를 가리키는 유일한 표지다.
- **`oauth_redirect_base_url` 의 7행** — GitHub App 콜백 URL 이 와일드카드를 받지 않아 PR 프리뷰가
  각자 등록할 수 없다는 **상류 API 의 제약**. 정책이 이름 붙인 「복원 불가능한 지식」 그 자체다.
- **`sanitize_preview_id` 의 5행** — `~`·`&`·`#` 가 콜백 URL 의 질의 문자열을 위조할 수 있어
  이스케이프가 아니라 **거부**한다는 보안 판단.
- **`worker_token` 의 「Empty means "this deployment has no worker"」 2행** — 빈 값이 fail-open
  이 아니라 fail-closed 라는 불변식.
- **`read_secret` 의 「k8s commonly projects secrets as files」** — 왜 파일 폴백이 있는지.
- **`Mode` 의 stub/real 설명 2행** — stub 이 실제와 갈리는 지점(충실도 경계)은 정책이 유지 대상으로
  명시했다.
