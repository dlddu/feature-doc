### 유지 목록 (묶음마다 필요 사유 한 문장)

**`0001`~`0008`** (L 66)
- `0001` 전건(11) — 자격증명 행은 사용자 범위로만 질의된다는 격리 불변식, 타임스탬프가 초 단위라는 사실(`INTEGER` 로는
  밀리초와 구별되지 않는다), 세션 id 가 곧 쿠키 값이라 되돌릴 수 없어야 한다는 것, 설치 토큰과 키 평문을 저장하지
  않는다는 봉투 암호화 불변식, 감사 로그가 append-only 라는 것 — 지우면 새 열·새 질의가 이 불변식을 모르고 깬다.
- `0002` 전건(4) — Setup URL 의 `installation_id` 를 위조할 수 있다는 상류 API 의 함정이 이 표가 존재하는 이유다.
- `0003` 「display only, never a hard cap」 — 추정치를 상한으로 쓰는 틀린 판단을 막는다.

  FIFO 순서, 단계 행은 코드 목록에서 씨앗을 뿌리므로 마이그레이션으로 단계를 더하지 않는다는 것.
- `0005` 재실행 덮어쓰기 — 버전 축을 더하면 「어느 문서를 보여 주나」가 모호해진다는 결과를 막는다.
- `0006` 전건(9) · `0007` 생성본/사용자본 분리와 행 단위 선택 · 병합 행 보존 — 두 표를 합치거나 JSON 을 행으로(또는
  반대로) 바꾸는 판단이 재현성 해시·이월 질의를 깨는 이유와, 병합된 행을 지우면 되돌림과 「이미 본 자리」가 사라진다는 것.
- `0008` 요청/데이터 분리 · 외래 키 부재 · 중간 상태 부재 — 「분석 중」과 「결과 없음」의 구분, FK 가 더하는 것 없이
  삭제 순서만 묶는다는 것, 리스가 끊긴 요청의 회수 경로.
- 인덱스 앞 한 줄들(`0004`·`0007`·`0008`) — SQLite 는 인덱스를 이름으로 부르지 않아 그 인덱스를 쓰는 질의를 grep
  으로 찾을 수 없다. 인덱스를 바꾸거나 지우러 온 사람에게 의존하는 질의를 알려 주는 유일한 자리다.
