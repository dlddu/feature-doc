# 판정 상세 — 가짜 벽 철거 (원장의 「경로 벽」 분류 정정 + `crypto.rs`) · 2026-09-22

reconciler task `rct_20260922-0007`(모델 `tbm_feature-doc-comment-redundancy`). 이 패스는 **주석을
새로 판정한 몫이 작고**(1파일 13행), 본체는 **원장이 사실과 어긋나게 적고 있던 「경로 벽」 분류를

## 무엇이 어긋나 있었나

`tools/check-data-format-change.py` 는 PR 이 사람 리뷰를 받아야 하는지 가르는 판정기이고, 원장은 그
규칙 집합을 근거로 잔여 일부를 **「주석 패스가 스스로 풀 수 없다」**고 적어 왔다. 그런데
**#125(`78183d2`, 2026-09-22)가 그 판정기를 D1·D6 두 규칙으로 축소**하면서
`CORE_FILES`(D2) · `D3_PATTERNS`(D3) · `STORAGE_CRATES`(D4) · `is_pvc()`(D5) 를 **전부 삭제**했다
(판정기 자신의 주석도 58 → 36행). 18차 패스(#124)는 그 **줄 수만** 재실측해 넣고
「**D5·D2 벽의 분류 자체는 다시 재지 않았다 — 새 판정기로 음성 대조를 다시 돌리는 것은 다음
감지·계획의 몫이다**」로 명시해 넘겼다. 이 패스가 그 수신자다.

어긋남은 **줄 수가 아니라 분류**였다. 그래서 #124 가 합을 104 → 82 로 고친 뒤에는 원장의 산술
(행 열의 합 · 「전역 − 잔여」)이 **전부 초록인 채로** 분류가 틀린 상태였다 — 원장 「읽는 법」이
스스로 적어 둔 사각지대(「지문이 어긋났는데 줄 수는 맞다면 …」)의 실례다.

## `backend/src/crypto.rs` — 13행 → 7행 (제거 6)

13차 패스가 [보류분의 판정 결과](2026-09-20-credential-llm-key-axis.md)에 **제거 6 · 유지 7** 로
판정을 마쳐 두고, 당시 살아 있던 D2 때문에 옮기지 못한 몫이다. **판정을 새로 하지 않고 그 문면을
그대로 적용**했다.

### 제거 6행

- **시그니처 재진술 `///` 2건** — "Seals *plaintext* under a fresh DEK, wrapping that DEK with *kek*"
  는 `seal(kek, plaintext)` 가, "Recovers the plaintext from an *Envelope*, unwrapping the DEK with
  *kek*" 는 `open(kek, env)` 가 그대로 말한다(복원 경로 ①).
- **모듈 머리의 동작 서술 3행** — 「fresh random 256-bit DEK … sealed under AES-256-GCM … wrapped with
  the KEK」. `seal()` 본문이 그 순서 그대로다(①).
- **`(AC4.3)` 꼬리표** — 작업 흔적. `docs/prd/04-platform.md` AC4.3 이 원본이다(②).
- **`// Best-effort scrub of the plaintext DEK now that it is wrapped.`** 인라인 — 모듈 머리의 불변식
  문장에 **흡수**했다(2벌 → 1벌). 바로 아래 `dek.iter_mut().for_each(|b| *b = 0);` 가 「무엇을」을,
  모듈 머리가 「왜 best-effort 인가」를 맡는다.
- `Envelope` doc 의 **rustdoc 링크 전용 교차 참조**(대괄호 링크 `seal` · `open`) — 이름에서 복원되므로
  링크를 위해 문장을 남기지 않는다(본문 「유지 대상」).

### 유지 7행

- **모듈 머리 불변식 4행** — persist 되는 것은 wrapped DEK 와 ciphertext 뿐이고 평문 비밀·평문 DEK 는
  디스크에 닿지 않으며, DEK 는 wrap 즉시 지워진다. **「best-effort」** 는 Rust 가 소거를 보장하지
  않는다는 사실이라 코드에서 복원되지 않는다(본문 「복원 불가능한 지식 — 봉투 암호화 불변식」).
- **`Envelope` 2행** — 「저장되는 전부이며, KEK 없이는 어느 것도 비밀을 드러내지 않는다」. 필드 이름은
  무엇이 저장되는지만 말하고, **그 집합이 비밀을 드러내지 않는다**는 계약은 말하지 않는다.
- **`open` 1행** — 「변조(GCM 태그 불일치)나 잘못된 KEK 는 **오류가 되지, 쓰레기 평문이 되지 않는다**」.
  호출자가 기대는 계약이고 `?` 하나에서 복원되지 않는다.

## 왜 한 패스인가

원장 정정만 하면 **줄 수가 한 줄도 움직이지 않아** 전역 지문이 그대로다. 이 모델의 to-be 는
`docs/comment-policy/` tree hash 라 정책 편집만으로도 재감지가 돌지만, **정정이 옳았는지를 대상
시스템에서 확인해 주는 것은 아무것도 없다**(레포 게이트 0건). `crypto.rs` 를 같은 PR 에 넣으면
**「벽이 걷혔다」는 주장을 그 PR 자신이 CI 에서 증명**한다 — 판정기가 이 PR 에 `✅` 를 내는 것이
곧 반증 가능한 실측이다.

  있어 **마이그레이션 축(0009~0013, 사람 게이트)과 내용이 얽힌다** — 그 축과 함께 볼지 따로 볼지는

**12:43:47Z 에 ruleset 의 context 가 `review/manual-approval` 로 바뀌어 풀렸다**(ruleset `updated_at`
실측). `#124` 는 12:46:57Z 에 착지했다. 이 PR 이 겪은 문제는 아니지만, **원장이 필수 status 이름을

필수 status 이름은 `/rules/branches/main` 에서.
